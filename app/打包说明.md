# 颐养年店铺管理 - 打包与发布说明

## 发布到蒲公英

### 1. 构建 APK

在项目根目录执行：

```bash
./publish_new_version.sh [版本号] [更新说明]
```

示例：

```bash
./publish_new_version.sh 1.0.1 "首次发布"
```

脚本会：
- 从 `app/env.json` 生成 `app/lib/core/env_generated.dart`，并校验不含 REPLACE_ME
- 更新 `app/pubspec.yaml` 中的版本号
- 执行 `flutter clean` 和 `flutter pub get`
- **构建 Debug APK**（输出到 `app/build/app/outputs/flutter-apk/app-debug.apk`）

**发布包与本地调试完全一致**：为避免「同一设备、同一网络下本地能连、蒲公英安装包不能连」的问题，发布脚本与 `run_android.sh` 使用**同一构建类型**：
- 本地：`flutter run` → 安装的是 **Debug** 构建
- 发布：`flutter build apk --debug` → 上传的也是 **Debug** 构建

因此从蒲公英下载安装的 APK 与本地 `./run_android.sh` 安装的为同一类型，网络、配置等行为一致。配置来源也相同（均通过 `env_generated.dart`）。

### 2. 上传到蒲公英

构建完成后，有两种方式上传：

**方式一：网页上传**
1. 打开 https://www.pgyer.com
2. 登录后上传 APK 文件
3. 填写版本说明

**方式二：自动上传（推荐）**
1. 复制 `pgyer_config.sh.example` 为 `pgyer_config.sh`
2. 在 `pgyer_config.sh` 中填入 API Key（获取地址：https://www.pgyer.com/account/api）
3. 运行 `./publish_new_version.sh` 时会自动上传到蒲公英

### 3. 启动页与设置页的版本检测（蒲公英）

若使用蒲公英分发，可在 `env.json` 中配置 **PGYER_APP_KEY** 与 **PGYER_API_KEY**，实现：

- **启动时**：闪屏页自动调用蒲公英接口检测是否有新版本；若有则弹窗展示版本号与更新说明，「立即更新」打开 https://www.pgyer.com/yyndpgl-android 下载页，「取消」进入首页。
- **设置页**：「检查更新」同样会走蒲公英接口。

获取方式：
- **PGYER_APP_KEY**：蒲公英后台 → 应用管理 → 该应用 → 安装设置
- **PGYER_API_KEY**：蒲公英后台 → 账户设置 → API 信息

配置后需重新执行 `./scripts/generate_env_dart.sh`（或通过发布脚本自动生成）使配置生效。

### 4. 配置自定义检查更新（可选）

若不使用蒲公英，可使用自建 `version.json`，APP 内「设置」页的「检查更新」会请求该 URL：

1. 准备一个 `version.json` 文件，格式示例：
```json
{
  "latest_version": "1.0.1",
  "android_url": "https://www.pgyer.com/xxx",
  "download_page_url": "https://www.pgyer.com/xxx",
  "release_note": "更新说明"
}
```

2. 将 `version.json` 部署到可公网访问的 URL

3. 在 `app/env.json` 中添加：
```json
"UPDATE_CHECK_URL": "https://你的域名/version.json"
```

4. 构建时使用 `--dart-define-from-file=env.json` 传入配置

### 5. 使用 env.json 构建

若需包含 UPDATE_CHECK_URL 等配置，构建时使用：

```bash
cd app
flutter build apk --release --dart-define-from-file=env.json
```

或使用脚本（脚本会尝试读取 env.json，若存在则传入）。

## Supabase 连接问题排查（Failed host lookup）

若 APP 报错「Failed host lookup / No address associated with hostname」或「无法连接服务器」：

- **若错误信息里显示的域名是真实 Supabase 地址**（如 `xxx.supabase.co`，不是 REPLACE_ME）：说明配置已正确打进包，多为**当前网络/DNS 无法解析或访问该域名**。可尝试：换一个 WiFi、用 4G/5G、或关闭 VPN 后再试；若 Supabase 项目在 ap-south-1（孟买）等区域，部分网络访问不稳定，可考虑将项目迁到 Singapore (ap-southeast-1)。
- **若错误信息里是 REPLACE_ME 或明显占位**：说明发布时 `env_generated.dart` 未正确生成，请确保 `app/env.json` 已填写且执行 `./publish_new_version.sh` 前本机已安装 node 或 python3。

详细排查：

### 1. 先到 Supabase 控制台确认项目状态

1. 登录 [Supabase Dashboard](https://supabase.com/dashboard)
2. 打开 **颐养年** 对应项目（yiyangnian's system）
3. 若页面顶部有 **「Project is paused」** 或 **「项目已暂停」**：
   - 点击 **「Restore project」/「恢复项目」**
   - 免费版 7 天无活动会自动暂停，恢复后需等几分钟再试 APP
4. 若未暂停仍连不上，看下一步（区域差异）

### 2. 区域差异（与高佳欣对比）

| 项目   | Supabase 区域        | 域名示例 |
|--------|-----------------------|----------|
| 高佳欣 | ap-southeast-1（新加坡） | uebeyflmmpesjolcrhnp.supabase.co |
| 颐养年 | ap-south-1（孟买）      | qkdtppdiihwrpierueyv.supabase.co |

同一账号下两个项目在不同区域，部分网络/VPN 对 **ap-south-1** 解析或访问不稳定，对 **ap-southeast-1** 正常。

**可选方案**：在 Supabase 里新建一个项目，区域选择 **Singapore (ap-southeast-1)**，把表结构/数据迁过去，再把 `env.json` 里的 `SUPABASE_URL`、`SUPABASE_ANON_KEY` 换成新项目的，重新打包。这样与高佳欣同区域，行为更一致。

### 3. 本机快速验证

在电脑终端执行（把域名换成你的项目）：

```bash
# 能否解析颐养年项目域名
nslookup qkdtppdiihwrpierueyv.supabase.co

# 对比：高佳欣项目域名
nslookup uebeyflmmpesjolcrhnp.supabase.co
```

若第一个无结果或报错、第二个正常，说明当前网络对颐养年所在区域解析异常，可优先恢复项目或迁到新加坡区域。
