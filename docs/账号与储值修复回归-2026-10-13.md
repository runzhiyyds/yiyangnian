## 修复内容

- 退出先完成 SDK 本机会话清理和持久会话删除，远端退出、推送解绑不阻塞页面；解绑不再临时向 FCM 获取 Token。删除重复的“切换账号”入口，保留退出确认、忙碌状态与登录页体验账号入口。登录等待正在进行的本地退出；晚到的旧退出事件不覆盖新的登录。
- 会话存储保持原项目键，串行处理 SDK 的异步保存/删除，防止上一次删除覆盖下一次登录。账号变化清除页面缓存、共享读取缓存和客户树状态。
- 客户详情将多个重复聚合查询加逐笔消费读取，合并为 3 个并行基础查询和批量消费读取；储值详情从 5 个重复来源读取减为 3 个独立来源。金额、最早日期和剩余次数沿用原口径，批量消费按 500 行分页以防截断。关闭的旧客户编辑页不能回填账号已清空的缓存。
- 仓库共享 30 秒内存读取缓存，最多 80 项，按实际账号 UID、仓库方法及业务日期范围区分；合并相同的并发读取，返回独立列表。写入完成或异常均使读取缓存失效，手动刷新绕过缓存。登录、写入没有新增自动重试。
- 库存首屏成功显示后，延迟 1 秒在后台预加载客户树和分析页；不阻塞启动或登录。预加载用批量储值汇总替代逐客户读取金额，独立查询并行执行。一次业务保存只发出一次刷新通知。
- 客户树只在账号、请求代次和数据版本仍匹配时应用完整快照；分析页也检查账号、月份/周期请求代次，防止晚到响应覆盖新筛选结果。TTL 淘汰与预加载消费不被当作业务变更。
- 客户、分析页刷新失败保留最后一次成功数据并提供重试；周期汇总与日历有独立错误提示，注明旧数据日期，不再把读取失败转换成 0 或空日历。储值选项读取失败可以重新加载，保留表单；储值保存早期校验也捕获网络异常并防止连续提交。

## 新增储值失败根因及数据库变更

体验账号复现后端 `42703`：`record "new" has no field "quantities"`。用户提供的线上 `validate_owned_small_item_array()` 与故障版本一致：同一函数供储值表和进货表使用，单个 AND 表达式引用了仅进货表存在的 `NEW.quantities`。

修复先进入 `TG_TABLE_NAME = 'inventory_purchase_records'` 分支，再检查进货专有字段。保留数组对齐校验、同账号小项校验，以及历史进货单只修改非商品信息的兼容规则。

- 已更新 016，避免新项目再次安装故障函数。
- 已提供并在该 Supabase 项目执行 `018_fix_owned_item_trigger.sql`。用户确认已有可恢复备份并提供原函数后执行；原函数另有本地副本供对象级回退。
- 018 事务仅替换这一个函数；有函数/绑定预检、5 秒锁超时、30 秒执行上限。没有重跑 013、016、017，没有修改历史业务行、RLS、外键或函数授权。
- SQL Editor 返回 `Success. No rows returned`；随后体验账号真实新增储值及读取验证成功，手机表单保存也成功。

## 复验方式

在 app 目录先运行 `./scripts/generate_env_dart.sh`，再执行：

```bash
flutter test
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter drive --driver=test_driver/integration_driver.dart --target=integration_test/module_regression_test.dart -d <设备ID> --keep-app-running
flutter drive --driver=test_driver/integration_driver.dart --target=integration_test/storage_form_test.dart -d <设备ID> --keep-app-running
```

真机保持解锁、APP 前台和调试连接。手机省流设置限制后台移动数据；锁屏条件下曾出现 APP 与 shell 探针行为不同，不能据此断言域名或网关整体故障。不要通过卸载/清数据执行验证。

数据库运行测试只启动本地 WASM PostgreSQL，不连接线上：

```bash
npm install --prefix /tmp/yiyangnian-pg-regression @electric-sql/pglite@0.5.9 --no-audit --no-fund
PGLITE_MODULE=file:///tmp/yiyangnian-pg-regression/node_modules/@electric-sql/pglite/dist/index.js node tools/test_owned_item_trigger.mjs
```

本轮安装使用正常 Release 构建，保留本地 2.0.3 版本及用户打包说明；未上传新的蒲公英版本。生产应用配置、凭据、APK 与缓存均不进入 Git 提交。
