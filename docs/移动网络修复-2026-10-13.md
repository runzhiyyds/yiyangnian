# 移动网络修复（2026-10-13）

## 原因与方案

在 NOH AN01、Android 12、移动数据下，用独立 Android HTTPS 探针访问原项目 `/auth/v1/health`：DNS 返回 `104.18.38.10` 和 `172.64.149.246`，请求约 393 ms 后被重置。探针保留证书与主机名校验，不提交账号密码。该现象在 Flutter 外复现，支持网络路径问题，不能据此确定具体重置节点或策略。

沿用高佳欣已验证的思路，为本项目新增独立入口 `yiyangnian-api.pet-food-advisor.asia`，绑定独立 Worker `yiyangnian-api`，固定上游为原项目 `jhntjagskjklbrsgturh.supabase.co`。没有迁移数据库、升级 Supabase 套餐或执行 013/016/017 等生产迁移，也没有修改高佳欣入口与原产品根域名路由。

同一手机移动数据下，新入口 `/health` 返回 HTTP 200，约 1393 ms；`gatewayReached`、`upstreamReached` 均为 true，上游 401，Worker 到上游约 43 ms。两段 HTTPS 路径已验证可达，真实业务鉴权另行验证。本机电脑最初查询了未创建的新主机名，之后系统解析仍曾失败；手机解析已正常，不把电脑的缓存/解析结果当成手机路径结论。

## 客户端接入

- 本地私有 `app/env.json` 的 URL 切换为新入口，仍使用原项目客户端公开密钥。继续通过 `app/scripts/generate_env_dart.sh` 生成编译配置，本地调试与 Release 来源一致；真实生成文件、密钥及蒲公英配置不提交本次任务。
- 对这个固定上游入口，显式保留 `sb-jhntjagskjklbrsgturh-auth-token`。原项目直连或其他项目仍采用 SDK 默认会话键，不把其他项目会话混入本项目。
- 增加原生连接期限 6 秒、单请求期限 12 秒，响应体也受期限控制；超时在传输层取消，不让晚到密码响应改变登录状态。网关只转发一次，客户端没有新增登录/写入自动重试。
- 登录按钮防止重复提交，移除仅限制 UI 等待却不取消底层请求的外层超时；网络错误显示可读提示，Auth 错误显示服务端 message，不把完整异常字段直接展示给用户。
- 库存、客户、储值、消费、统计和演示/正式账号的数据口径、缓存域与 RLS 保持原有实现。真实业务记录不用于验证性新增/删除。

## 验证与回退

本地 46 项 Flutter 测试、17 项 Worker 测试通过；后续真机与构建结果见本文件的验证结果记录。测试使用 `flutter drive --keep-app-running`，避免 `flutter test -d 手机` 在结束时卸载应用。驱动选择实际注册了测试扩展的 isolate，并在结果收集期间持续恢复新建 isolate 的启动暂停，避免 Firebase 后台任务或大响应 JSON 解析任务停在调试断点。

测试入口为 `app/integration_test/gateway_test.dart`，测试配置放在本地文件，包含 `NETWORK_TEST_EMAIL`、`NETWORK_TEST_PASSWORD`，需要检查原会话时设置 `NETWORK_EXPECT_OLD_SESSION: true`。独立内存测试会话不替换手机原持久会话。SDK REST 请求会自动刷新过期会话，核验账号需要在这一刷新后执行，不能直接拿刚恢复的过期 JWT 调用 `auth.getUser`。

```bash
cd /Users/guochenyuan/Desktop/颐养年/app
./scripts/generate_env_dart.sh
flutter drive --driver=test_driver/integration_driver.dart --target=integration_test/gateway_test.dart --keep-app-running -d <设备ID> --dart-define-from-file=<本地测试配置>
```

回退客户端时恢复本地配置中的原 URL，再重新生成并构建；会话仍在原项目键下。Worker 可恢复 `wrangler.readonly.jsonc` 对应的 `src/index.js` 版本，不需要改根域名或数据库。原移动网络路径仍可能失败，回退本身不等于修复原网络。

开始工作时已有本地版本号、打包说明及生成配置文件修改；本次提交保留这些用户修改，只同步网络接入、必要依赖/测试与文档，不提交真实生成配置、APK 或缓存。
