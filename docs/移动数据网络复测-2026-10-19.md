# 移动数据网络复测（2026-10-19）

## 同机只读对比

设备：华为 NOH-AN01、Android 12、中国移动 5G。测试前 Wi-Fi 与移动数据均开启，实际默认走公司 Wi-Fi；测试时临时关闭 Wi-Fi，确认系统默认网络为 `MOBILE[NR] CONNECTED`，结束后恢复 Wi-Fi 开启。没有输入账号密码，也没有新建、编辑、撤销业务记录。

使用 `tools/android-network-probe/Probe.java` 在手机系统网络栈中交替请求两条 HTTPS 路径（完整读取响应，保持正常证书/主机名校验）：

| 路径 | 8 次结果 | 耗时 |
| --- | --- | --- |
| 原 Supabase `/auth/v1/health` | 8 次 `SocketException` | 约 499–783 ms 后断开 |
| 现有中转 `/health` | 8 次 HTTP 200 | 首次 1810 ms；后续约 259–318 ms |

这说明**本次、这台手机、此移动网络下**，恢复直连不是可行修复。探针未证明哪个网络节点中断了直连，也不能保证中转在其他时间/网络始终可用。现有 2.0.4 在移动数据下库存连续刷新 6 次、四主页面各切换 3 轮，均未出现可见错误，未复现用户此前的间歇故障。

## 客户端调整

- 固定项目中转入口上的无请求体 `GET`/`HEAD`：连接异常或 HTTP 502/503/504 时，网络层最多再请求一次；两次尝试共用一个 16 秒期限，并在超时或用户取消时停止。非中转入口、业务错误响应及所有写请求不在网络层重放。普通写请求仍为 12 秒期限。
- 仍使用页面层通用重试的读取，默认尝试次数由 3 次降为 2 次，以免网络层已重试后再出现过长的等待和请求风暴。它仍只对既有的临时错误类型生效。
- 库存页后台预加载从首屏成功后 1 秒调整为 3 秒，并先加载客户树、再加载分析，避免同时发起两组后台请求。已有账号隔离、30 秒内存读缓存、业务变更失效和页面手动刷新机制保持不变；不持久化过期库存数字。
- 移除小项新增/修改页面对写请求的通用自动重试，以免服务端已写入但响应丢失时重复执行。

## 验证及边界

- Flutter 全量 79 项测试通过；改动文件静态检查无问题。网络层新增连接失败、网关 502、业务 400、写入不重放和共享期限测试；页面层补充重试次数测试。
- Release APK 构建成功（60.9 MB）。本地构建时 `integration_test` 开发依赖引发正式包 Java 编译错误；仅在构建期间临时移除该测试依赖，构建后已恢复 `pubspec.yaml` 与占位生成配置，不将该临时修改提交。构建包覆盖安装到同一手机，未清除 APP 数据，原登录状态仍在。
- 新包在移动数据下库存连续刷新 6 次、客户/分析/设置/库存四主页面均可进入且无可见网络错误；最后调整页面重试上限并重建覆盖安装后，又完成库存 4 次刷新及四主页面各一次检查。样本有限，未实际触发一次中转连接故障，因此真机尚不能证明新增的自动重试发生过；重试分支由单元测试覆盖。
