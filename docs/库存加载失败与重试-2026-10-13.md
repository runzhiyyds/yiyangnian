# 库存加载失败与重试（2026-10-13）

## 现场结论

手机上的 2.0.2 在移动数据下停在库存首页，显示“操作未完成，请稍后重试（错误码：3E576B26）”，没有重试入口。实际路由使用 `InventoryOptionsScreen`，并非已有重试按钮的 `InventoryScreen`。

该编号来自异常字符串的 `hashCode`，不是 Supabase 状态码。可用手机日志中没有保留触发该编号的底层异常；保留账号数据覆盖安装调试包后，七类库存查询已正常返回。因此具体哪条历史请求、哪种底层异常触发了 3E576B26 尚未确认，不能据此断言网络封锁、数据库迁移或数据损坏。

真机回归还捕获到一次新入口 HTTPS 连接 6 秒超时；同一手机独立 Android HTTPS 探针对两个业务入口返回 HTTP 200（约 1.6～2.9 秒）。这支持间歇网络/首次连接故障，而非持续不可达；该超时是否就是历史编号对应的原异常仍未确认。未扩大登录或写入的自动重试。

可确认的客户端问题是：七类读取中任一项最终失败，首页就只展示错误文字；没有用户重试入口，也没有保留刷新前已加载内容。HTTP ClientException、网关超时及不可用响应还可能落入未知错误分支。

## 修复

- 首次加载失败提供“重试”，正常页面提供“刷新库存”和下拉刷新。
- 刷新时保留原列表、搜索和筛选；失败显示提示与“重试”，明确当前内容来自上次成功加载。不会把请求失败展示成空库存。
- 合并重复加载；加载过程中收到数据失效通知时，结束后补一次刷新。
- 切换账号立即清除旧内容；请求完成前核验账号，旧账号响应不能写入新账号页面。
- 将 ClientException、网关 504、502/503 等可识别故障转为可读提示；未知错误仍保留诊断编号。
- 失败诊断包含大项/小项/储值/消费/进货/补充入库/出库阶段、耗时、异常类型、后端错误码及同一诊断编号。Release 不打印完整异常正文，不记录密码、令牌或业务记录。

## 验证

- 53 项 Flutter 单元/组件测试通过，覆盖首次失败重试、保留原内容与搜索、重复点击、失效通知排队和旧账号响应隔离。
- 修改涉及的 Dart 文件静态检查无问题。
- Android Release 构建通过（60.7 MB），保留用户本地 2.0.2 版本配置。
- 真机用例完整通过（约 18 秒，驱动退出码 0）：首次失败后点击重试恢复真实库存；刷新失败保留原列表，再次重试恢复。测试通过独立内存客户端模拟小项读取的网关超时，恢复阶段走真实移动数据与业务入口。没有新增、修改、删除业务记录；原账号和原非会话本地设置均已比对保留。

本次未变更 Supabase 数据库、账号或网关部署，未上传蒲公英。用户已有版本号、打包说明及生成配置修改保留。
