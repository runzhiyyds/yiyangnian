# 账号隔离迁移执行指南

## 目标

迁移后，每个登录账号只读写自己的客户、储值、消费、进货、出库、补充入库、分类选项和推送设备。APP 仍只有一个门店，但账号之间不共享业务数据。

## 为什么不能直接自动执行

现有线上表没有 `owner_id`，数据库无法自行判断历史正式数据应该归属哪个账号。迁移脚本因此使用全 0 UUID 占位并默认中止，必须由管理员显式填写历史数据所属账号的 `auth.users.id`。

## 执行顺序

1. 在 Supabase Dashboard 的 Authentication 用户列表中确认历史正式数据所属账号 UUID。
2. 对生产数据库做可恢复备份，并优先在副本或测试项目演练。
3. 打开 `docs/supabase_migrations/016_account_isolation.sql`。
4. 只替换 `account_isolation_context` 中的 `production_owner` 全 0 UUID；不要修改其他 UUID。
5. 在维护窗口执行整份脚本。脚本使用单个事务，任何检查或约束失败都会整体回滚。
6. 使用正式账号、体验账号和一个空白测试账号分别登录验证：
   - 正式账号只能看到自己的历史数据。
   - 体验账号只能看到演示数据。
   - 空白账号看不到其他账号数据，并拥有自己的默认大项。
   - 同一台 Android 设备切换账号后，推送 Token 转移到当前账号；退出后该 Token 停用。
7. 验证新增客户、进货、出库、储值和消费后，新增行的 `owner_id` 均等于当前 `auth.uid()`。

## 上线前核对

- `production_owner` 不是全 0 UUID，且存在于 `auth.users`。
- 若数据库中存在“演示-”或 `JH90` 数据，体验账号 UUID 必须存在。
- 三个进货数组长度全部一致；迁移后的触发器会拒绝不一致的新写入。
- 旧推送 Token 会被停用，设备下次登录后由 APP 重新绑定，不会猜测旧 Token 属于哪个账号。
- 不要把账号密码、访问令牌或服务角色密钥写入迁移脚本、提交或 PR。

## 回退边界

脚本提交前发生错误会自动回滚。提交后若要撤销账号隔离，必须从执行前备份恢复；不要直接删除 `owner_id` 或放宽 RLS，这会重新暴露跨账号数据。
