# 账号隔离迁移执行指南

## 目标

迁移后，每个登录账号只读写自己的客户、储值、消费、进货、出库、补充入库、分类选项和推送设备。APP 仍只有一个门店，但账号之间不共享业务数据。

## 生产归属的安全填写方式

现有线上表没有 `owner_id`，数据库无法自行判断历史数据归属。016 因此保留全 0 UUID 占位符，执行前必须用只读查询核验正式账号 UUID，并且只在 Supabase SQL Editor 的执行副本中替换。

不要把正式账号邮箱、UUID、密码、Token 或服务角色密钥提交到代码仓库。016 会核验正式 UUID 确实存在，并核验固定体验账号的 UUID、邮箱和确认状态；任一不匹配都会整体回滚。

## 执行顺序

1. 对生产数据库做可恢复备份或确认 PITR 可用；CSV 不能替代完整数据库备份。
2. 执行 `docs/supabase_migrations/013_demo_auth_user.sql`，创建并确认独立体验账号。脚本不会修改其他 Auth 用户。
3. 复制 `docs/supabase_migrations/016_account_isolation.sql` 到 SQL Editor，只在执行副本中把 `production_owner` 的全 0 UUID 替换为只读查询得到的正式账号 UUID；不要改仓库文件中的占位符或体验账号 UUID。
4. 确认 016 成功后，再执行 `docs/supabase_migrations/017_inventory_timeline_and_void_audit.sql`。
5. 使用正式账号、体验账号和一个空白测试账号分别登录验证：
   - 正式账号只能看到自己的历史数据。
   - 体验账号只能看到演示数据。
   - 空白账号看不到其他账号数据，并拥有自己的默认大项。
   - 同一台 Android 设备切换账号后，推送 Token 转移到当前账号；退出后该 Token 停用。
6. 验证新增客户、进货、出库、储值和消费后，新增行的 `owner_id` 均等于当前 `auth.uid()`。

## 上线前核对

- `production_owner` 已从全 0 UUID 替换为只读查询确认的正式账号 UUID。
- 体验账号必须由 013 创建且邮箱已确认。业务编号来自全局序列，`JH90` / `CZ90` / `XF90` 不能作为数据归属依据。
- 三个进货数组长度全部一致；迁移后的触发器会拒绝不一致的新写入。
- 旧推送 Token 会被停用，设备下次登录后由 APP 重新绑定，不会猜测旧 Token 属于哪个账号。
- 不要把账号密码、访问令牌或服务角色密钥写入迁移脚本、提交或 PR。

## 回退边界

脚本提交前发生错误会自动回滚。提交后若要撤销账号隔离，必须从执行前备份恢复；不要直接删除 `owner_id` 或放宽 RLS，这会重新暴露跨账号数据。
