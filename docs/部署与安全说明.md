# 颐养年 - 部署、安全与备份说明

## 一、Web 部署与「不让员工拿走数据」

### 1. Web 如何部署到公网（含中国大陆访问）

- **方式一：静态托管**
  - 在项目根目录执行：`cd app && flutter build web --release --dart-define-from-file=env.json`
  - 产物在 `app/build/web/`，把该目录下的所有文件上传到任意**静态网站托管**（如 Nginx、腾讯云 COS+CDN、阿里云 OSS、Vercel 等）。
  - 中国大陆可访问：若用国内服务器或 CDN，需完成**备案**；若用海外服务器则不备案也可，但国内访问可能较慢或被限。

- **方式二：仅本机或内网**
  - 不部署到公网，只在您电脑上 `./scripts/run_with_env.sh web`，用浏览器打开；或在内网一台机器上跑 Flutter Web，只给内网 IP 访问。这样外网（包括员工在家）访问不到。

- **关于「看不到域名 / 只有 Windows APP」**
  - 若希望员工**只能在你控制的设备上用**、拿不定数据：
    - **Windows 桌面版**：可做 Flutter Windows 应用（`flutter build windows`），把 exe 装在公司电脑上，不把 `env.json` 或 Supabase 配置交给员工；数据仍在 Supabase，但员工拿不到配置就无法自己搭一个客户端连你的库。
    - **不暴露 Supabase**：当前前端是直连 Supabase（URL + anon key 会打在打包的代码或 env 里）。若 Web 部署出去，懂技术的人可以从前端拿到 anon key 和 URL，自己连你的库。要彻底「不让别人连你的库」只能：① 不把带 Supabase 配置的版本给员工用；② 或加一层自己的后端，前端只调你的后端，Supabase 只在你自己的服务器上访问。

### 2. 加强登录鉴权与修改密码

- **修改当前登录密码（Supabase 后台）**
  1. 登录 [Supabase Dashboard](https://supabase.com/dashboard) → 选「颐养年」项目  
  2. 左侧 **Authentication** → **Users**  
  3. 找到对应用户（如 18613544351@163.com），点击进入  
  4. 点 **Send password recovery** 会发重置邮件；或使用第三方方式改密码后，在 Dashboard 里该用户处可**重置密码**（部分界面为「⋯」→ Reset password）  
  5. 设成**强密码**（大小写+数字+符号，至少 12 位）

- **改密码后 App 里要不要改？**
  - 当前代码里有**自动登录**（`auth_service.dart` 里默认账号密码）。若你改了 Supabase 里该用户的密码，但没改代码里的 `_defaultPassword`，自动登录会失败，用户会看到错误或跳到登录页。
  - **推荐做法**：  
    - 要么：改 Supabase 密码后，**不再在代码里写密码**，关掉自动登录，所有人（包括你自己）都在登录页**手动输入**强密码。这样密码只存在 Supabase 和用户脑子里，更安全。  
    - 要么：保留自动登录，则需在 `auth_service.dart` 里把 `_defaultPassword` 改成和新密码一致（不推荐，因为密码会进代码仓库）。

- **如何「强制密码鉴权」**
  - 现在已经是「必须登录 Supabase 才能看数据」；加强鉴权 = 使用强密码 + 不共享账号。  
  - 若希望「每次打开都输密码」：可以关掉自动登录（例如注释或删除 `autoSignIn()` 的调用），这样每次冷启动都会到登录页，必须输入邮箱+密码。

## 二、执行 005 迁移是否影响现有数据？如何备份？

### 1. 005 会不会影响现有数据？

- **不会。**  
  - `005_storage_big_item_options.sql` 只做两件事：  
    ① 新建表 `storage_big_item_options`（之前不存在）；  
    ② 向该表插入 3 条默认大项（藏红方、御至宝、元气植）。  
  - 没有修改、也没有删除任何已有表（如 `customers`、`storage_records`、`consumption_records` 等），所以**现有数据不会被改动或清空**。  
  - 储值记录里的 `storage_big_items` 仍然是 TEXT 数组，只是大项选项来源从代码里的写死列表改成了数据库表，对已有储值数据兼容。

### 2. Supabase 数据库如何备份？

- **Supabase 自带备份（付费项目）**  
  - Pro 计划有自动每日备份与 PITR，在 Dashboard → **Database** → **Backups** 可查看/恢复。

- **免费项目可用的备份方式**  
  1. **SQL 导出（推荐，简单）**  
     - Dashboard → **SQL Editor**  
     - 新建 Query，执行下面语句（会生成各表的查询结果，可复制或导出为 CSV）：  
       ```sql
       -- 导出客户（可复制结果或另存）
       SELECT * FROM customers;
       SELECT * FROM storage_records;
       SELECT * FROM consumption_records;
       SELECT * FROM storage_small_item_options;
       SELECT * FROM storage_big_item_options;  -- 执行 005 后才有
       ```  
     - 或使用 **Table Editor** 里每张表右上角的导出功能（若有）。

  2. **用 pg_dump（完整备份）**  
     - Dashboard → **Project Settings** → **Database** 里可以看到 **Connection string**（含密码）。  
     - 在本机安装 PostgreSQL 客户端后，用 `pg_dump` 连接该串，可导出完整 SQL 文件，例如：  
       `pg_dump "postgresql://postgres:[YOUR-PASSWORD]@db.xxx.supabase.co:5432/postgres" > backup.sql`  
     - 将 `backup.sql` 妥善保存（不要上传到公开仓库），需要时可用 `psql` 或 Supabase SQL Editor 恢复。

  3. **定期手动备份习惯**  
     - 每次重要操作前（如执行新迁移、大批量改数据），先在 SQL Editor 里对关键表做一次 `SELECT * FROM xxx`，把结果复制到本地文本/表格保存，或先导出一份 pg_dump。

## 三、运行脚本报错与正确用法

### 1. `no such file or directory: ./scripts/run_with_env.sh`

- 脚本在 **`app/`** 目录下，不在项目根目录。  
- **正确用法**：先进入 `app` 再执行脚本：
  ```bash
  cd /Users/guochenyuan/Desktop/颐养年/app
  ./scripts/run_with_env.sh web
  ```
  或 Android：
  ```bash
  cd /Users/guochenyuan/Desktop/颐养年/app
  ./scripts/run_with_env.sh android
  ```

### 2. `ActionChip` 的 `icon` 报错（已修复）

- 您当前使用的 Flutter 版本里，`ActionChip` 没有 `icon` 参数，已改为用 `label` 里放 `Row(Icon + Text)` 实现「添加大项」按钮，保存后重新执行：
  ```bash
  cd app
  ./scripts/run_with_env.sh web
  ```
  或 `./scripts/run_with_env.sh android` 即可正常编译运行。
