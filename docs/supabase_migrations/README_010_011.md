# 大项-小项层级迁移说明（010 + 011）

## 执行顺序

1. **010_small_item_big_item_fk.sql**：添加 `storage_big_item_id` 列
2. **011_backfill_small_item_big_item.sql**：从历史储值/进货记录中推导并回填归属

## 数据继承逻辑（011）

- 从 `storage_records`、`inventory_purchase_records` 中提取 (大项名, 小项ID) 配对
- 配对规则：大项/小项数组按索引一一对应；若长度不同，则用第一个大项匹配所有小项
- 每个小项取**出现次数最多**的大项作为归属
- 仅当大项名存在于 `storage_big_item_options` 时才更新（避免脏数据）
- 无历史配对的小项保持 `NULL`（未归类）

## 安全措施

- 使用 `BEGIN`/`COMMIT` 事务，出错可 `ROLLBACK`
- 创建备份表 `storage_small_item_options_backup_20250225`（可选，生产建议保留）
- 仅 `UPDATE`，不删除或清空数据
- 回填后输出统计信息到 Messages

## 回滚方式

若需恢复回填前状态：

```sql
BEGIN;
UPDATE storage_small_item_options so
SET storage_big_item_id = b.storage_big_item_id
FROM storage_small_item_options_backup_20250225 b
WHERE so.id = b.id;
COMMIT;
```

## 执行后验证

```sql
-- 查看已归类数量
SELECT count(*) FILTER (WHERE storage_big_item_id IS NOT NULL) AS 已归类,
       count(*) AS 总数
FROM storage_small_item_options;
```
