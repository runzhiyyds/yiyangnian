## 零、关闭邮箱确认（必做，无发信能力时）

本项目**没有**自助注册与邮件确认能力，请在 Supabase 关闭邮箱确认：

1. 打开 [Supabase Dashboard](https://supabase.com/dashboard) → 你的项目  
2. **Authentication** → **Providers** → **Email**  
3. **关闭**「Confirm email」（确认电子邮件）  
4. 点击 **Save**

然后任选其一：

- **重新执行** `docs/supabase_migrations/013_demo_auth_user.sql`（会补全体验账号「已确认」状态）  
- 或仅执行 `docs/supabase_migrations/015_auth_confirm_all_users.sql`（把已有账号全部标记为已确认）

## 一、在 Supabase 创建体验账号

任选一种方式。

### 方式 A：SQL（推荐，与演示数据一起初始化）

1. 打开 Supabase 项目 → **SQL Editor**
2. 执行 `docs/supabase_migrations/013_demo_auth_user.sql`
3. 看到 `体验账号已创建` 或 `已存在，跳过` 即成功

### 方式 B：Dashboard 手动创建

1. **Authentication** → **Users** → **Add user** → **Create new user**
2. Email：`user@example.com`，Password：`123456`
3. 勾选 **Auto Confirm User**（避免邮箱未确认无法登录）

## 四、建议体验路径

1. **TAB1 客户信息一览**：展开「演示-张阿姨」，查看储值与消费树
2. **新建储值**：选藏红方 + 演示小项，可看到剩余库存角标；保存后库存自动出库
3. **TAB2 库存管理**：查看进货、出库记录、小项库存余额
4. **TAB3 店铺数据分析**：查看近期储值/消费统计
5. **设置**：退出登录后再次登录，验证会话与数据持久化

## 常见问题

**Q: 登录提示 Email not confirmed / 请先到邮箱确认**  
A: 在 Supabase **Authentication → Providers → Email** 关闭 **Confirm email**，再执行 `015_auth_confirm_all_users.sql` 或重新执行 `013_demo_auth_user.sql`。

**Q: 登录提示 Invalid login credentials**  
A: 未创建 Auth 用户。请执行 `013_demo_auth_user.sql` 或在 Dashboard 创建同邮箱用户。

**Q: 登录成功但客户列表为空**  
A: 未执行 `014_demo_seed_data.sql`，或 RLS/迁移未完整执行。

**Q: 登录体验账号却看到其他客户/正式数据**  
A: 体验账号与正式账号在应用内**双向隔离**：体验账号仅见「演示-」数据，正式账号不会看到演示数据。覆盖客户一览、库存管理（含大项小项、进货/入库/出库、小项详情）、店铺分析等。若仍看到旧数据，请**退出登录后重新登录**以清空本地缓存。

**Q: 正式账号能看到演示数据吗？**  
A: 不能。正式账号会自动过滤掉所有「演示-」前缀及 JH90/CZ90/XF90 编号的记录。

**Q: 想清空演示数据重新导入**  
A: 再次执行 `014_demo_seed_data.sql` 即可（脚本内含清理逻辑）。
